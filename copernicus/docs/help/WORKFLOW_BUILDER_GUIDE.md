# Workflow Builder Guide

The Workflow Builder in Copernicus allows you to automate complex development tasks by chaining together various operations into executable workflows.

## Concepts

A workflow is composed of **nodes** and **edges**.
- **Nodes**: Represent individual steps or actions within your workflow (e.g., calling an AI agent, running a shell command).
- **Edges**: Connect nodes, defining the flow of execution.
- **Context Bag**: A `Map<string, string>` that stores and passes data between nodes. Think of it as a shared memory for your workflow.
- **Variable Interpolation**: You can access variables from the context bag or special built-in variables within node fields using double curly braces:
    - `{{__storyId}}`: The ID of the current story.
    - `{{__lastOutput}}`: The output from the previously executed node.
    - `{{__lastExitCode}}`: The exit code from the previously executed node (useful for `tool` nodes).
    - `{{__storyTitle}}`: The title of the current story.

## Node Types

Copernicus provides several node types to build your workflows:

-   **Agent**: Executes an AI agent with a given prompt.
    -   **Purpose**: Ideal for tasks requiring intelligent decision-making, code generation, summarization, or analysis.
    -   **Key Fields**: `Agent Name`, `Prompt`.
-   **Tool**: Runs a shell command.
    -   **Purpose**: For executing scripts, build commands, tests, or any command-line operation.
    -   **Key Fields**: `Command`, `Working Directory`.
-   **Decision**: Branches the workflow based on the output of a previous node or a condition.
    -   **Purpose**: Implements conditional logic, allowing different paths based on success/failure, specific keywords in output, etc.
    -   **Key Fields**: `Condition`, `True Branch`, `False Branch`.
-   **Trigger**: The starting point of any workflow.
    -   **Purpose**: Defines how and when a workflow begins. A workflow must always start with a Trigger node.
    -   **Key Fields**: (None directly configurable by user; automatically handles workflow start).
-   **Flow**: Sequences multiple operations.
    -   **Purpose**: Organizes and groups nodes, making complex workflows more readable and manageable.
    -   **Key Fields**: (Acts as a container for other nodes).

## Building Your First Workflow

Let's create a simple 3-node workflow: `Agent → Decision → Tool`. This workflow will ask an AI agent to generate a simple shell command, decide if the command is safe, and then execute it.

1.  **Start with a Trigger node**: Every workflow begins here.
2.  **Add an Agent node**:
    -   Connect it to the Trigger node.
    -   Configure the Agent:
        -   `Agent Name`: `coder` (or any available coding agent)
        -   `Prompt`: "Generate a shell command to list all files in the current directory."
3.  **Add a Decision node**:
    -   Connect it to the Agent node.
    -   Configure the Decision:
        -   `Condition`: `{{__lastOutput}} contains "ls"` (This is a simplified example; in a real scenario, you'd want more robust safety checks).
4.  **Add a Tool node (for "True" branch)**:
    -   Connect it from the "True" output of the Decision node.
    -   Configure the Tool:
        -   `Command`: `{{__lastOutput}}` (Executes the command generated by the Agent).
5.  **Add another Tool node (for "False" branch - optional)**:
    -   Connect it from the "False" output of the Decision node.
    -   Configure the Tool:
        -   `Command`: `echo "Unsafe command detected: {{__lastOutput}}"`
        -   `Working Directory`: `./`

-   **Story Implementation Pipeline**: A comprehensive workflow to guide you through the implementation of a user story, including coding, testing, and documentation steps.

## Context Variables Table

| Variable Name      | Description                                                                  |
| :----------------- | :--------------------------------------------------------------------------- |
| `{{__storyId}}`    | The unique identifier of the currently active user story.                    |
| `{{__storyTitle}}` | The title of the currently active user story.                                |
| `{{__lastOutput}}` | The standard output (stdout) from the immediately preceding node's execution.|
| `{{__lastExitCode}}`| The exit code from the immediately preceding node's execution (0 for success, non-zero for failure).|
| `{{<custom_key>}}` | Any custom key-value pair added to the context bag by a node.                |

## Time-Travel / Rewind

The Workflow Canvas provides powerful time-travel capabilities. Every execution step is snapshotted, allowing you to "rewind" to any previous state of your workflow. This is invaluable for debugging and understanding execution flow.

-   **Snapshots**: Each node execution creates a snapshot of the workflow's state, including the context bag.
-   **Rewind**: Select a past snapshot to revert the workflow to that state.
-   **Detached HEAD Warning**: Be aware that rewinding effectively creates a "detached HEAD" state for your workflow's execution history. While you can always fast-forward or restart, frequent rewinding requires careful management to avoid confusion.

## Troubleshooting

-   **Node Stuck in `running`**:
    -   Check if the underlying process (e.g., shell command, AI call) is still active.
    -   Ensure there are no infinite loops or external dependencies blocking execution.
    -   Review the node's output for any error messages or hanging prompts.
-   **Decision Not Branching Correctly**:
    -   Verify the `Condition` logic. Ensure variable names are correct and the comparison matches the expected output.
    -   Inspect `{{__lastOutput}}` in the context bag to see the exact value being evaluated.
-   **Empty Agent Output**:
    -   Check the agent's prompt for clarity and completeness.
    -   Ensure the agent has access to necessary context or tools.
    -   There might be a rate limit or API error; check the application logs.
